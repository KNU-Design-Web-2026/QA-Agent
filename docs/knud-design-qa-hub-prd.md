# KNUD Design QA Hub PRD

## 1. 제품 개요

KNUD Design QA Hub는 디자이너가 실제 배포된 KNUD 전시 사이트를 조작하면서, 화면의 정확한 위치에 시각 코멘트를 남기고 개발자가 재현 가능한 정보와 함께 확인하는 내부 협업 도구다.

대상 페이지를 복제하거나 정적인 목업으로 바꾸지 않는다. QA Hub 안의 뷰포트에서 실제 Vercel 배포본을 실행해 페이지 이동, hover, 클릭, 애니메이션, 반응형 동작을 그대로 검수한다.

## 2. 문제와 목표

### 문제

- 디자이너의 구두·메신저 피드백은 페이지, 화면 폭, 문제 위치, 배포 버전이 빠져 개발자가 재현하기 어렵다.
- Figma와 실제 배포본을 비교할 때 동일한 반응형 폭과 스크롤 위치를 맞추기 어렵다.
- 단순 스크린샷 코멘트는 실제 인터랙션의 문제를 설명하지 못한다.

### 목표

- 디자이너가 실제 배포본의 정확한 요소·영역에 30초 안에 코멘트를 남긴다.
- 개발자가 QA 항목 하나만 보고 동일한 배포본·경로·뷰포트·스크롤 위치를 재현한다.
- Figma 기준과 구현 화면의 차이를 근거 이미지와 함께 검토한다.
- 새 배포본에서 열린 QA가 해결됐는지 빠르게 재검토한다.

### 성공 지표

- QA 코멘트의 95% 이상이 추가 질문 없이 재현 가능하다.
- 코멘트 생성부터 개발자 확인까지의 중앙값이 1영업일 이하다.
- 배포 버전·뷰포트·경로가 누락된 코멘트 비율이 0%다.

## 3. 사용자와 권한

| 역할 | 권한 |
| --- | --- |
| 디자이너 | 프로젝트·배포본 열람, 코멘트·드로잉 작성, 본인 코멘트 수정, 해결 확인 |
| 개발자 | 모든 코멘트 열람·상태 변경, 담당자 지정, 재현 링크 열기, Agent 분석 실행 |
| 관리자 | 프로젝트·멤버·배포 대상·Figma 기준·알림 채널 관리 |

MVP에서는 초대받은 사용자만 접근한다. 공개 전시 사이트 방문자에게 QA UI나 데이터를 노출하지 않는다.

## 4. 핵심 사용자 흐름

### 4.1 디자이너의 QA 작성

1. QA Hub에서 프로젝트와 Vercel 배포본을 선택한다.
2. 기준 뷰포트 `1920`, `1350`, `1020`, `600`, `400px` 중 하나를 선택한다.
3. 실제 사이트를 탐색하고 인터랙션을 확인한다.
4. `코멘트 모드`를 켜고 핀을 클릭하거나 문제 영역을 드래그한다.
5. 코멘트, 우선순위, 유형(시각·인터랙션·콘텐츠·기준 확인)을 입력해 저장한다.
6. Hub가 스크린샷, 경로, 뷰포트, 스크롤, 배포 SHA, DOM anchor를 자동 저장한다.

### 4.2 개발자의 수정·검토

1. 개발자는 새 QA 알림 또는 대시보드에서 항목을 연다.
2. `원본 배포본에서 열기`를 선택해 같은 URL·뷰포트·스크롤 위치로 재현한다.
3. 상태를 `진행 중`으로 바꾸고 수정한다.
4. 새 배포본을 연결하고 `검토 요청` 상태로 변경한다.
5. 디자이너는 이전 캡처·Figma 기준·새 배포본을 비교해 `완료` 또는 `재오픈`한다.

## 5. MVP 기능 요구사항

### 5.1 리뷰 캔버스

- 실제 배포 URL을 iframe으로 렌더링한다.
- 아래 고정 뷰포트를 정확한 CSS pixel 크기로 제공한다: `1920×1340`, `1350×900`, `1020×1370`, `600×980`, `400×880`.
- 뷰포트는 확대해서 보여줄 수 있지만 iframe 내부의 CSS viewport 크기는 변경하지 않는다.
- URL 입력과 페이지 내 탐색을 지원한다.
- Figma 기준 이미지의 표시·숨김·불투명도 조절·차이 비교 모드를 제공한다.

### 5.2 주석과 코멘트

- 점 핀, 사각형 영역, 화살표, 자유 드로잉, 텍스트 강조를 제공한다.
- 코멘트는 댓글 스레드, 멘션, 우선순위, 유형, 상태, 담당자를 가진다.
- 주석은 페이지 좌표가 아니라 요소 anchor와 정규화 좌표를 함께 저장한다.
- 주석 클릭 시 우측 패널의 해당 스레드가 열리고, 패널 항목 클릭 시 캔버스의 위치로 이동한다.
- 코멘트 작성 시 현재 캡처 이미지를 자동 생성한다.

### 5.3 재현 정보

각 코멘트에 아래 값을 필수 저장한다.

| 항목 | 설명 |
| --- | --- |
| deployment | Vercel deployment URL, ID, Git SHA, 생성 시각 |
| page | path, query string, 문서 제목 |
| viewport | CSS width, height, device scale factor, 확대 비율 |
| position | scroll x/y, anchor selector 또는 `data-qa-id`, 요소 사각형, 정규화 좌표 |
| evidence | 작성 시점 PNG, Figma node URL(선택), Agent 차이 이미지(선택) |

### 5.4 상태와 알림

- 상태: `열림 → 진행 중 → 검토 요청 → 완료`, 필요하면 `재오픈`.
- 새 코멘트·멘션·검토 요청·재오픈은 앱 알림을 즉시 생성한다.
- MVP의 외부 알림은 Slack 또는 이메일 중 하나를 선택해 연결한다.

### 5.5 Agent 보조 기능

- 시각 비교 결과를 근거 이미지와 함께 첨부한다. Agent가 임의로 디자인 결정을 확정하지 않는다.
- 코멘트를 `개발 수정`, `디자인 기준 확인`, `의도 확인`으로 분류한다.
- 같은 배포본·화면·anchor의 유사 코멘트를 중복 후보로 제안한다.
- 개발자용 재현·수정 요청 문장을 한국어로 요약한다.

## 6. QA Bridge

서로 다른 도메인의 QA Hub와 전시 사이트 간 iframe 제약을 해결하기 위해, 전시 사이트에는 최소한의 QA Bridge를 조건부로 포함한다.

- Hub가 발급한 짧은 수명의 QA 세션 토큰이 있을 때만 활성화한다.
- `postMessage`의 origin과 토큰을 검증한다.
- 현재 경로, 스크롤, 클릭 대상의 `data-qa-id`, 요소 사각형, 배포 SHA를 Hub에 전달한다.
- 일반 방문자 화면에는 툴바·주석·추적 데이터를 렌더링하지 않는다.
- `data-qa-id`는 시각적 클래스명 대신 `site-header`, `navigation-toggle`, `main-artwork`처럼 의미 있는 안정 식별자를 사용한다.

## 7. 비기능 요구사항

- QA Hub는 Chrome 최신 버전의 데스크톱 사용을 우선 지원한다.
- 키보드로 코멘트 패널, 핀 선택, 상태 변경을 수행할 수 있어야 한다.
- reduced motion 사용자는 주석 전환·패널 애니메이션을 최소화한다.
- 스크린샷과 코멘트는 프로젝트·권한 단위로 격리한다.
- 전시 사이트의 일반 성능·SEO·분석에는 QA Bridge가 영향을 주지 않아야 한다.

## 8. 데이터 모델 초안

```text
Project
  └─ ReviewTarget (배포 URL, 환경, Git SHA)
      └─ ReviewSession (뷰포트, 경로, Figma 기준)
          └─ CommentThread (anchor, 좌표, 상태, 담당자)
              ├─ Annotation (핀·영역·드로잉)
              ├─ Comment
              └─ Evidence (스크린샷·Figma 비교 이미지)
```

## 9. 범위 제외

- Figma 디자인 파일의 직접 수정
- 전시 사이트의 소스 코드 자동 수정·자동 배포
- 공개 사용자용 피드백 수집
- 모든 브라우저·모바일 네이티브 앱의 완전한 지원

## 10. 단계별 출시

### Phase 1 — 검수 기반

- 초대 기반 로그인
- 단일 KNUD 프로젝트와 Vercel Production 배포본
- 다섯 기준 뷰포트, 핀·영역 코멘트, 스크린샷, 상태 관리
- QA Bridge와 재현 링크

### Phase 2 — 협업 강화

- Figma 기준 이미지 오버레이
- 댓글·멘션·Slack 또는 이메일 알림
- 배포본 간 비교와 검토 요청

### Phase 3 — Agent·플러그인

- Figma-구현 시각 비교 Agent
- 중복·우선순위·수정 요청 요약 Agent
- Figma 플러그인에서 선택한 노드와 QA 코멘트 연결

## 11. 출시 승인 기준

- 디자이너가 실제 Production 배포본의 600px 화면에서 헤더를 드래그해 코멘트를 남길 수 있다.
- 개발자가 저장된 링크로 같은 배포본·경로·뷰포트·스크롤 위치를 재현할 수 있다.
- 일반 전시 사이트 방문 시 QA Bridge와 주석 UI가 보이지 않는다.
- 새 배포본에서 코멘트를 `검토 요청`으로 전환하고 디자이너가 완료 처리할 수 있다.
